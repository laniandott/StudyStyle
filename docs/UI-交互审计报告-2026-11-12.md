## 0. 结论先行

**当前版 vs 昨天截图不是同一份。** `docs/screenshots/*.png` 生成于 11-11 23:56–23:57，而 `index.html` 改于 11-12 08:18、`styles.css` 改于 11-12 08:27、`app.js` 改于 11-12 09:53。截图**是上一版**。当前版新增了整套「科目笔记本」体系（侧栏科目树 + 顶部横向书架 + 6 色主题色），而 `DESIGN-SYSTEM.md` 全文 **0 次**提及「笔记本/notebook」——**规范本身落后于实现**，这是本次审计最大的结构性发现。

**视觉骨架（铁律一/二/三、色彩 token、禁用项）执行得很干净**，可以逐条对上。但落地层面有 **5 个 P0 级问题**（都实测复现，非推测）：

1. **移动端底部 tab 栏被「科目笔记本 +」按钮挤破**——`.nav-caption-row` 在 ≤480px 未被隐藏，压在 3 格 tab 栏右侧（实测 x=307, w=83）。
2. **顶栏「当前页名」完全缺失**——规范 §6.2 要求顶栏左侧放 h3 页面名，实现里 `top-actions` 因 `justify-content:space-between` 塌到左边，顶栏右侧 950px 全空。规范 §10.2 又说"顶栏只保留主题/帮助/设置/新增"，两处自相矛盾。
3. **等级筛选两套入口同屏并存**——侧栏 `#bagNav` 7 项 + 内容区 chips 行 7 项，违反 §10.3「等级筛选全局只剩一套」。
4. **「全部科目」三处入口**——侧栏科目树 + 顶部书架 + 队列行内 `.notebook-chip`，违反「一个功能一个入口」。
5. **复习弹窗 `Space` 键在真实场景失效**——规范 §10.9 要求 Space 展开大纲，但焦点在 `#recallInput`（textarea）时 `isTypingTarget` 判定为 true 直接 return，实测按 Space 停留在第 1 步。

另有一个**暗藏的功能性 bug**：卡片库「筛选」按钮的角标 `.filter-count-pill` **只在整页重渲染时才更新**，抽屉内改下拉框不重渲染 → 角标永久缺失。以及**历史页/卡片库行仍带 3px 彩色左边框**（`--row-accent`），在规范明令「禁止彩色左边框 / 队列行用 8px 色点替代」的今日页已被修掉后，这两处成了全站残留的七彩来源。

**G6（P2）`<dialog>` 缺少「打开时焦点管理」与「关闭后焦点归还」的自定义**。实测浏览器原生 `dialog` + `showModal()` 已提供焦点陷阱和关闭后焦点归还（实测焦点正确回到 `.queue-open` 触发按钮）✔ —— 但 `askConfirm` 的 `dialog.addEventListener('close', ...)` 每次调用都 `addEventListener(..., {once:true})`（app.js:1354），重复调用会累积监听器（once 只解绑自身）。

**G7（P2）卡片库「筛选无结果」空态无按钮**。实测 `#libraryEmptyResult` 内容是纯文本「没有符合条件的卡片。清除筛选（标签：编程 · 关键词：xxx）后可看到全部 5 张。」—— 说了"清除筛选"却没有按钮（`empty-filter has BUTTON? false`）。虽然上方工具条有「清除筛选」按钮，但规范 §10.10「空状态必须给下一步按钮」在此处不成立。

**G8（P0）卡片库筛选角标永久失效**。`.filter-count-pill` 由 `renderLibrary` 生成（app.js:516），`activeFilterCount` 在**整页渲染时**计算。抽屉内的 select 变更走 `filterLibrary()`（app.js:1674），**不重渲染** → 实测选标签后 `filter-count-pill exists? false`，角标**根本不出现**（因为初始 `activeFilterCount=0` 时就不渲染这个 span）。规范 §10.6 明确要求「『筛选』按钮带角标」。同时 `toggle-lib-filters` 的抽屉展开态与 `activeFilterCount>0` 存在竞态：实测选完标签后点「筛选」按钮，抽屉无法收起（因为 `filterOpen = uiFolds.libraryFilters || activeFilterCount > 0` 强制打开，app.js:487）。

**G9（P1）1000 张卡片全量渲染**。实测 `library rows rendered: 1000`，`#libraryList` 高 107001px。搜索过滤耗时 44ms（可接受），但**无虚拟滚动/分页**，DOM 节点 1000×。移动端会更糟。

**G10（P1）长标题在卡片库截断过狠**。`.library-card-snippet` 单行 clamp（`-webkit-line-clamp: 1`），大纲预览基本失去意义。

**G11（P2）`.cloze-mask` 的 `aria-label` 硬编码为"点击显示答案"**（app.js:233），但点击后是 toggle revealed 状态，"显示"与"隐藏"共用一个 label，无状态播报。

### 3.2 无障碍缺口

> **对 team-lead「≤480 触控目标 min-height 44px ✅ 达标」的修正**：该结论只覆盖了 `.nav-item`（styles.css:3468，全站唯一一处 ≤480 段的 `min-height:44px`）。实测其余可点元素仍不达标：`.level-chip` 28px 高（styles.css:1051）、`.notebook-pill` 32px（3735）、`.queue-open` 32px（1234）、顶栏 `.icon-button` 32px（634）、`.caption-action-btn` 22px（3673）、**`.band-limit` 13×16px**（唯一能调每日上限的入口）。规范 §10.11 要求「移动端所有可点区域 ≥44×44px」——**仅底栏 3 格达标，其余 6 类未达标**。

**A1（P0）焦点环在深色模式不可见**。全局 `:focus-visible { outline: 2px solid var(--c-brand-500) }`（styles.css:264-268）在 `--c-surface` 上仅 **2.16:1**，低于 WCAG 2.2 SC 1.4.11 的 3:1 门槛。修法：改用 `var(--c-focus-ring)`（浅色 brand-100 / 深色 brand-300，深色下 7.54:1 ✔），或深色下换成 brand-300。

**A2（P0）`.bag-link` 与 `.notebook-chip` 是 DIV/SPAN 却承载点击**。实测侧栏 9 个 `.bag-link` + 队列行 10+ 个 `.notebook-chip` 全是 `DIV`/`SPAN`。规范 §10.13「所有交互元素为原生 button/input/select/a」。后果：**键盘 Tab 完全无法到达等级筛选和科目筛选**，屏幕阅读器也不会播报它们是控件。

**A3（P0）`Space` 键在复习弹窗第 1 步失效**（见 §1.6）。UI 上「查看大纲」按钮明写 `<kbd>Space</kbd>`，但实际焦点在 textarea → `isTypingTarget` 拦截 → 按 Space 只是在打空格。这是**明摆着骗用户的快捷键提示**。

**A4（P1）`.cloze-mask` 以外的挖空无障碍尚可，但 `role="radio"` 缺 roving tabindex**。5 个评分按钮 `role=radio` + `aria-checked` ✔，但**无 `tabindex` 管理**（实测 5 个都是 null），Tab 要按 5 次才能过评分区；ARIA radiogroup 规范期望 roving tabindex + 方向键。方向键 ←/→ 已被占用为「分数 ±5」（规范 §10.9 明确），所以 radiogroup 方向键与调分冲突 —— 这是规范自身冲突（见 S 组）。

**A5（P1）`.row-menu` 无焦点管理**。`⋯` 菜单打开后（app.js:1414-1421）焦点**不进入菜单**，Esc 不关闭菜单（Esc 只在 dialog 分支处理），菜单项 `role="menuitem"` 但容器 `role="menu"` 无 `aria-activedescendant`。键盘用户打开后只能盲按 Tab。

**A6（P1）触控目标普遍不足 44px**。实测移动端：icon-button 32px、level-chip 28px、notebook-pill 32px、queue-open 32px、caption-action-btn 22px、**band-limit 13×16px**（「每日上限 25」的可点数字，是唯一能调上限的入口）。规范 §10.11「移动端所有可点区域 ≥44×44px」。

**A7（P2）`.field-label` 与 input 间距 6px，但批量制卡的两个 input 无 label**。`#batchMdNotebook` / `#batchMdTags`（app.js:595）只有 placeholder 无 label/aria-label。规范 §10.13「每个 input 有可见 <label>（不用 placeholder 代替）」。搜索框 `#cardSearch` 有 `aria-label` ✔（但规范 §10.13 也要求可见 label）。

**A8（P2）`aria-labelledby` 齐全但 `reviewTitle` 动态内容**。`#reviewTitle` 的 `textContent` 在 `showReviewCard` 里赋值 ✔，但 `<h2 id="reviewTitle">` 初始为空 → 首帧 dialog 无可访问名。

**A9（P2）`prefers-reduced-motion` 覆盖完整** ✔（styles.css:270-279）。**`focus-visible` 未覆盖 `outline:none` 的元素**：`.select-input` / `.text-input` / `.text-area` 用了 `outline: none`（styles.css:1781），只靠 box-shadow 表达焦点 —— box-shadow 焦点环在深色下是 `rgba(70,48,207,.14)` 硬编码，**不随主题变**，深色下几乎不可见。

**A10（P2）`role="status"` 用于错误**。toast 是 `role=status`（礼貌），但里面装的是「操作出错：xxx」这类错误 —— 错误应 `role="alert"`（打断）。

**A11（P2）`.score-button.selected` 用 `box-shadow: inset 0 0 0 2px #fff`** —— 规范 §6.11 明确授权 ✔，但写死 `#fff` 违反 token 化。

**A12（P2）`.mastery-seg` / `.heat-cell` 无文本等价物**。等级分布堆叠条只有颜色，无 `aria-label` 汇总；heatmap 14 格仅靠 `title` 属性。

## 4. 信息架构评估

### 4.1 当前结构

```
顶栏（主题 / 帮助 / 齿轮 / 新增卡片）        ← 缺左页名，右侧 950px 空
├─ 侧栏
│  ├─ 工作区：今日复习 / 全部卡片 / 复习记录
│  ├─ 科目笔记本：全部科目 / 默认笔记本 / [+新建]
│  ├─ 按等级筛选：全部 / 待首次…熟悉 (7)
│  └─ 同步状态
└─ 内容区（4 视图）
   ├─ 今日复习：标题行 → 【科目书架】→ 任务带 → 等级 chips → 队列 → 洞察折叠
   ├─ 全部卡片：标题 → 【科目书架】→ 等级 chips → 搜索条 → 抽屉 → 列表 → 批量制卡折叠 → 归档折叠
   ├─ 复习记录：标题 → 【科目书架】→ 时间轴
   └─ 设置与同步：4 组设置（2×2 grid）
```

### 4.2 判定

**层级深度：可接受。** 4 个视图 + 5 个弹窗，最大深度 3 层（视图→折叠→抽屉），没有过深。

**入口过多：确实存在，且集中在一类对象上——「筛选器」。** 当前一个用户想表达"我要看生物科里已熟悉的卡片"，需要理解 **3 个并列筛选维度**（科目 / 等级 / 标签+日期+排序），它们分布在 **6 个物理位置**：

| 维度 | 位置数 | 具体位置 |
|---|---|---|
| 科目 | **3** | 侧栏科目树 / 顶部书架（今日+卡片库+历史 三页都有）/ 队列行内 notebook-chip |
| 等级 | **3** | 侧栏等级列表 / 今日页 chips 行 / 卡片库 chips 行 |
| 标签 / 日期 / 排序 | 1（抽屉内 3 个 select） | 卡片库筛选抽屉 |

**「全部科目」具体重复**（你点名要查的）：侧栏 `#notebookNav` 首项「全部科目 16」+ 顶部 `.notebook-shelf` 首项 pill「全部科目 16」+ 队列行内每张卡的 notebook-chip。三个「全部科目」在**同一屏**内同时可见且语义完全相同。

**「等级筛选」具体重复**（你点名要查的）：侧栏 7 项 + 今日页 chips 7 项 + 卡片库 chips 7 项。侧栏项与 chips 项**文案、色点、数量全同**，纯粹是同一功能的两个渲染位置。

**概念重复**：
- 「新增卡片」3 处入口：顶栏（全局）、卡片库页头 `data-action="add"`（app.js:508）、空态里的「新增第一张」/「创建第一张卡片」。规范 §10.2 说「顶栏 + 新增卡片保留，**全局唯一新增入口**」→ 卡片库页头那个是多余的（app.js:508）。
- 「随机抽卡」3 处：顶栏已删 ✔（规范裁决正确），但任务带右区（app.js:381）、卡片库页头（app.js:507）、空态按钮（app.js:409）各一处。规范 §10.2 裁决说「收敛到卡片库页」，实现却在**今日页任务带也保留**了 → 与裁决直接冲突。
- 「设置」2 处：顶栏齿轮 + 设置页内「外观与数据」组里的「切换深色外观」按钮。主题切换在设置页和顶栏各一处。

**一个"入口过多"的正面反例**（做得好、应保留）：**「开始复习」在今日页只有 1 处**（任务带 primary），符合 §10.1「任一视图不得出现两个同等重量的主按钮」。

### 4.3 建议的目标结构（一套筛选器 + 一个新增入口）

```
顶栏：[当前页名 h3]                    ← 补左页名
      主题 / 帮助 / 齿轮 / +新增卡片    ← 齿轮与设置页内的主题按钮二选一

侧栏：
  工作区：今日复习 / 全部卡片 / 复习记录
  科目本：  全部科目
           ├ 生物 (11/16)
           └ 默认笔记本
  按等级筛选：全部 / 待首次…熟悉
  ─── 同步状态

内容区：
  今日复习：标题行 → 任务带 → 队列 → 洞察折叠       ← 删 chips 行、删科目书架
  全部卡片：标题 → 搜索条 → 列表 → 折叠区            ← 等级只在侧栏，标签/日期/排序只在抽屉
  复习记录：标题 → 时间轴
  设置与同步
```

核心改动一句话：**筛选器只保留侧栏一套（桌面）/ chips 一套（移动）**，科目本不再做顶部书架行 —— 侧栏科目树 + 队列行内 chip 已经够了。
